## Before claiming a story

- The parent runs as `gpt-6.2-astra`. When spawning a builder, explicitly select `gpt-6.2-sol`. For each review, explicitly select `gpt-6.2-astra` in a separate, fresh session with only the review packet and read-only instructions. Use the runtime's model selector at dispatch. Putting a model name in a message is insufficient. Record the selected models and session IDs from the runtime. If the surface silently inherits a different model, cannot select it, or cannot supply a fresh context, return `CONFIG_BLOCKED` before claiming.
- Check authenticated read access to the exact GitHub repository and Jira project, the available Draft PR and Jira transition/comment operations, and the product verification commands. Use one active build run per repository and engine. Check the scheduled task's run history or equivalent active-run evidence before claim. If another run owns the batch, yield. If a remote operation has an uncertain outcome, read back the branch, PR or Jira status before retrying.
- In **inspect**, read the ranked candidates and evaluate their gates once. Demonstrate model selection by actually dispatching a Sol session to read the base SHA and an independent Astra session to read that SHA from an isolated review packet. Use fresh contexts and the roles' inspect instructions. Return the runtime evidence, repository, eligible/skipped keys with reasons and missing capabilities. Keep Jira, GitHub and the checkout read-only. An empty backlog can still exercise this probe. Inspect consumes model usage.
- In **build**, read the full candidate for the exact `PROJECT`, `Ready/Listo`, `agent-ready`, and exactly one supported engine label, `engine-openai`. Require explicit matching repo, approved design and acceptance criteria. Skip existing branches, PRs or active work for that key. Scan by `Rank ASC` across result pages. If `ISSUE` was supplied, inspect only that key, without waiting for other candidates.

## Dispatch

1. Gather all blockers from directed Jira links, fields and text. Fetch each blocker. A human prerequisite must be Done/Finalizada. An unfinished agent prerequisite needs a unique verified parent PR in this repo under the portable contract, including parents assigned to other engines. Use fresh `origin/master` if there are no unfinished blockers. Otherwise pin the SHA of a parent branch containing every required parent SHA and use that branch as the PR base.
2. For each eligible key create its own branch `codex/<KEY>` and Git worktree at that base SHA. Verify the absolute worktree path, checked-out branch, HEAD and clean parent checkout. Re-read the candidate, dependencies and published parent SHAs immediately before moving Jira to In Progress. Verify the resulting state before dispatch. Leave skipped issues in Listo.
3. Start each Sol builder with a fresh context and only its full role contract, original frozen Jira spec and URL, criteria, dependency record, base branch/SHA, assigned branch and absolute worktree. Record key → builder session → worktree. Dispatch eligible builders concurrently, up to three distinct admissions across the run. Never replace a finished/failed admission with a fourth. With capacity remaining, follow the portable contract's 10-minute polling and shared 5 h 40 min deadline for pending agent PRs. Continue reviews while waiting. Report a runtime interruption truthfully.

## Publish and review each story

1. Verify the builder's diff and test evidence in its worktree. Only the parent may minimally update an existing `AGENTS.md` when implemented behavior warrants it. Run the resulting prescribed checks and record commands and exit codes. The parent handles commits, push, Draft PRs and Jira transitions. Never write to a parent PR's branch. Keep changes confined to the assigned branch.
2. Publish one Draft PR against the selected base. Include exact lines `Factory Engine: openai` and `Factory Jira: <KEY>`, the Jira URL, criteria mapped to evidence, tests, risks, AGENTS action and each parent key, PR, branch and pinned SHA in review order. Read the actual published PR back from GitHub, verify repo, draft, base, head branch and full head SHA, then move Jira to AI Review.
3. Fetch the published PR head from GitHub, verify its SHA, and obtain the complete PR diff against the published base. Give a fresh Astra reviewer the reviewer contract, original spec, constraints, PR URL, base and head SHAs, actual diff and test/CI evidence. Supply additional **read-only** context if needed. Exclude builder and prior review conversations. Never accept an orchestrator or builder self-review.
4. For `CHANGES_REQUESTED`, resume the original Sol session in the same worktree. The parent handles any AGENTS-only correction. Re-run checks, push to the same branch and send the new published head to a new Astra reviewer. Allow three correction rounds after the first review. If the original session/worktree is lost or the fourth verdict still requests changes, retain the Draft PR, record why and mark Blocked.
5. On `PASS`, re-read the PR before the transition. Verify it is still open and draft, with the reviewed base and head, and all required checks passing for that revision. If the diff changed, discard the verdict and review the current diff before promotion. If evidence is missing, retain AI Review or record Blocked. Otherwise post the reviewed SHA, tests and verdict, move Jira to Human Review and read back the status. Report each admitted/skipped key and the fields required by the portable contract. An empty verified selection yields `NO_WORK`. Merge, conflict resolution, deployment and Finalizada belong to the human.
